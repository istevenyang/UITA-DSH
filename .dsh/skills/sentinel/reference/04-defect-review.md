# 04 · 缺陷审视（准度 / 噪音 / 自愈 / 不可达复核）

对步骤 1–3 产物进行交叉复核并落盘 `04-defect-review.md`：

1. **准不准**：核对每条候选缺陷与风险是否真实命中变更代码路径，是否具备可证伪断言（哪条断言会红、红在何处）。
2. **噪音剔除**：将纯性能观察项（衰减 <30%）、自动化脚本自身维护项从产品风险中剥离。
3. **需求覆盖缺口复核**：核对 `missing` / `partial` RP 的三证完整性与可证伪断言，缺证则降级为 `unverified` 并列入「覆盖未验证清单」。
4. **不可达（`unreachable`）逐条复核**：
   - 仅**未消除的遗留风险**需要走不可达忽略复核；
   - 逐条核查 UI 入口检索、调用点实参面、系统/对端触发前提；证据不充分一律改判为可达（`ui_reachable` / `device_reachable`）。
